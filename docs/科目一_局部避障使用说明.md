# 科目一局部避障使用说明

科目一当前实现为机体坐标系下的最小闭环：Horizon 点云持续检测障碍；无相关障碍时透传合作方的正常控制命令；发现相关障碍时，本地采样曲率规划器临时接管；任何关键输入异常或无安全轨迹时输出零速。

> **安全边界**：实测雷达外参、车体尺寸、离地障碍高度、膨胀半径、速度/曲率和下游看门狗未审核前，不得接通执行机构。

## 1. 代码位置与逻辑

| 模块 | 代码 | 作用 |
|---|---|---|
| 点云障碍提取 | `src/ugv_subject1_perception_mvp/src/obstacle_detector_node.cpp`、`grid_extractor.cpp` | PointCloud2 变换到 `base_link`，做 ROI/高度/车体裁剪和栅格计数 |
| 局部避障与仲裁 | `src/ugv_subject1_avoidance_mvp/src/local_avoidance_node.cpp`、`local_avoidance.cpp` | 采样常曲率轨迹，碰撞检查、评分，并在正常命令/避障/停车之间原子选择 |
| LIO/TF 适配 | `src/ugv_localization_mvp` | 提供规范 `odom→base_link`；局部避障本身只使用 `base_link` 数据 |
| 启动与参数 | `src/ugv_subject1_bringup/launch/subject1*.launch.py`、`config/subject1.yaml` | 连接 Horizon、LIO、感知和避障节点 |

数据流：

```text
Horizon /livox/lidar (PointCloud2)
  → TF 转到 base_link
  → ROI/高度/车体裁剪
  → 栅格内点数统计
  → /subject1/obstacles

/subject1/obstacles ───────────┐
/subject1/next_waypoint_base ──┼→ 常曲率轨迹规划与最终仲裁 → /cmd_vel
/subject1/nominal_cmd_vel ─────┘
```

感知节点只接受：有唯一 FLOAT32 `x/y/z` 字段、内存布局合法、来源坐标系非空、时间戳非零且严格递增、能查到同时间 `base_link←点云坐标系` TF 的 PointCloud2。非法点云不产生新障碍输出，使下游因输入过期而安全停车。

栅格中心落入前方走廊时，`/subject1/obstacle_detected=true`，但这只是诊断。真正是否接管由规划器判断：它先检查直行轨迹与所有障碍栅格是否碰撞；只有直行相关障碍才启动避障采样。

规划器在 `[-max_curvature, +max_curvature]` 中均匀采样常曲率轨迹，沿每条轨迹用“车体矩形 + inflation”检查碰撞。无碰撞轨迹按终点距航点、航向误差、曲率和最小间距评分，选择最低分轨迹，并输出：

```text
linear.x  = speed_mps
angular.z = speed_mps × curvature
```

最终仲裁规则：

| 条件 | `/cmd_vel` |
|---|---|
| 无相关障碍，合作方正常命令新鲜、有限且为平面运动 | 原样透传 `linear.x`、`angular.z` |
| 有相关障碍，存在无碰撞轨迹 | 使用本地避障命令 |
| 全部轨迹被阻挡 | 全零 |
| 障碍或航点缺失、过期、错 frame 或数值非法 | 全零，不回退到正常命令 |
| 当前需透传，但正常命令缺失、过期、非有限或带其他非零分量 | 全零 |

时间戳为零、重复或倒退的障碍物/航点样本会被丢弃，也不会刷新接收时刻；节点最多沿用上一份有效输入，直到它超过 `input_timeout_s`（当前 `0.30 s`）后归零。换言之，坏时间戳不会立即覆盖好数据，但持续坏数据一定会在超时后停车。

规划、诊断和最终命令在同一个 20 Hz 定时回调中完成，因此运行图中不需要第二个 `/cmd_vel` 仲裁节点。科目一运行时必须确保没有其他节点发布 `/cmd_vel`。

## 2. 主要接口

| 话题 | 类型 | 含义 |
|---|---|---|
| `/livox/lidar` | `sensor_msgs/msg/PointCloud2` | Horizon 点云输入 |
| `/subject1/obstacles` | `geometry_msgs/msg/PoseArray` | `base_link` 下的占用栅格中心 |
| `/subject1/obstacle_detected` | `std_msgs/msg/Bool` | 前方走廊障碍诊断 |
| `/subject1/next_waypoint_base` | `geometry_msgs/msg/PointStamped` | 合作方输入；下一航点已转换到 `base_link` |
| `/subject1/nominal_cmd_vel` | `geometry_msgs/msg/Twist` | 合作方正常控制命令 |
| `/subject1/avoidance_active` | `std_msgs/msg/Bool` | 避障或安全停车分支已激活 |
| `/subject1/avoid_cmd_vel` | `geometry_msgs/msg/TwistStamped` | 本地避障候选，仅供诊断 |
| `/subject1/selected_trajectory` | `nav_msgs/msg/Path` | 选中轨迹，仅供诊断 |
| `/cmd_vel` | `geometry_msgs/msg/Twist` | 最终命令；m/s、rad/s |

`/subject1/next_waypoint_base` 必须使用 `header.frame_id=base_link`，时间戳非零且严格递增，并以高于超时阈值的频率刷新。正常命令只能使用有限的 `linear.x` 和 `angular.z`，其余四个分量必须严格为 0。

科目一配置把 `map_odom_manager.initial_transform_valid` 设为 `false`，所以启动后不会自动发布 `map→odom`。只有收到审核过的 `/localization/map_odom_update` 后才发布；本地避障不依赖该变换。

## 3. 当前关键参数

参数文件：`src/ugv_subject1_bringup/config/subject1.yaml`。

### 点云感知

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `input_timeout_s` | 0.30 s | 有效点云超时告警；下游障碍输入也在 0.30 s 后失效 |
| `tf_timeout_s` | 0.10 s | 点云 TF 查询上限 |
| `roi_min_x/max_x` | 0.20 / 8.00 m | 前后 ROI |
| `roi_min_y/max_y` | -3.00 / 3.00 m | 横向 ROI |
| `min_z/max_z` | 0.10 / 1.50 m | `base_link` 下障碍高度带 |
| `self_min_x/max_x` | -1.00 / 1.00 m | 自车裁剪 x 范围 |
| `self_min_y/max_y` | -0.60 / 0.60 m | 自车裁剪 y 范围 |
| `cell_size` | 0.15 m | 栅格边长 |
| `min_points` | 3 | 占用栅格最少点数 |
| `corridor_min_x/max_x` | 0.30 / 4.00 m | 诊断走廊纵向范围 |
| `corridor_half_width` | 0.80 m | 诊断走廊半宽 |

### 避障与仲裁

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `publish_rate_hz` | 20.0 | 规划/仲裁频率 |
| `input_timeout_s` | 0.30 s | 障碍、航点接收超时 |
| `nominal_cmd_timeout_s` | 0.30 s | 合作方正常命令超时 |
| `speed_mps` | 0.10 m/s | 避障轨迹速度 |
| `max_curvature` | 1.00 1/m | 采样曲率上限 |
| `curvature_samples` | 31 | 曲率样本数 |
| `horizon_m` / `step_m` | 3.00 / 0.10 m | 轨迹长度/采样间距 |
| `footprint_half_length_m` | 1.00 m | 车体半长候选值 |
| `footprint_half_width_m` | 0.60 m | 车体半宽候选值 |
| `inflation_m` | 0.30 m | 障碍安全膨胀 |
| `goal/heading/curvature/clearance_weight` | 1.00 / 0.50 / 0.15 / 0.70 | 轨迹评分权重 |

车体尺寸、高度带和 ROI 当前只是候选值，必须用实测值替换。

## 5. 启动命令

准备已确认的 Horizon 白名单 JSON 和审核过的 `base_link→livox_frame` 六自由度外参：

```bash
ros2 launch ugv_subject1_bringup subject1_horizon.launch.py \
  start_driver:=true \
  start_lio:=true \
  driver_config:=/绝对路径/已确认的horizon白名单.json \
  driver_allow_auto_discovery:=false \
  publish_lidar_static_tf:=true \
  lidar_extrinsics_provenance:=外参测量记录编号 \
  base_to_lidar_x:=实测值 \
  base_to_lidar_y:=实测值 \
  base_to_lidar_z:=实测值 \
  base_to_lidar_roll:=实测值 \
  base_to_lidar_pitch:=实测值 \
  base_to_lidar_yaw:=实测值
```

必须替换全部中文占位符。launch 会把 LIO 的 `msg_type` 强制为 `1`，并把原始 TF 隔离到 `/lio_raw/tf`。如果驱动和 LIO 已由其他进程管理，可传 `start_driver:=false start_lio:=false`，但外部 LIO 必须等价地使用 PointCloud2 模式并隔离原始 TF。

本地避障本身不消费 LIO 里程计，但仍必须有准确的 `base_link←livox_frame` 静态 TF，才能把点云障碍放到正确的车体坐标系。

## 6. 启动后调试

先断开执行机构：

```bash
ros2 node list
ros2 topic type /livox/lidar
ros2 topic hz /livox/lidar
ros2 param get /scan_registration msg_type
ros2 run tf2_ros tf2_echo base_link livox_frame

ros2 topic hz /subject1/obstacles
ros2 topic hz /subject1/next_waypoint_base
ros2 topic hz /subject1/nominal_cmd_vel
ros2 topic echo /subject1/obstacle_detected
ros2 topic echo /subject1/avoidance_active
ros2 topic echo /subject1/avoid_cmd_vel
ros2 topic echo /subject1/selected_trajectory
ros2 topic echo /cmd_vel
ros2 topic info -v /cmd_vel
```

预期 `/cmd_vel` 为 `geometry_msgs/msg/Twist`，且只有 `local_avoidance_node` 一个发布者。

### 常见故障

| 现象 | 优先检查 | 正确处理 |
|---|---|---|
| 有点云但无 `/subject1/obstacles` | PointCloud2 `x/y/z` 字段、时间戳、`base_link←livox_frame` TF、节点警告 | 修复输入/TF，不要放宽失效保护 |
| 地面被大量识别为障碍 | 外参、`min_z`、车体坐标轴 | 先修外参，再用实测 bag 调高度带 |
| 车身/履带被识别为障碍 | `self_*` 裁剪范围、外参 | 按实测 footprint 调整 |
| 远处噪点频繁触发 | `min_points`、`cell_size`、ROI、高度带 | 用录制点云逐项调，不要先减小 inflation |
| 无障碍仍为零速 | 正常命令是否持续刷新且仅有平面分量、障碍/航点是否新鲜 | 恢复合格输入 |
| 障碍出现但仍透传 | 障碍是否与直行膨胀 footprint 相交、坐标轴/尺寸是否正确 | 核对障碍位置和 footprint |
| 遇障后为零速 | 可能全部采样轨迹被阻挡 | 这是预期安全行为；先检查环境/参数，禁止强行前进 |
| 避障方向错误 | `base_link` 轴向、航点、角速度正方向 | 断开执行机构核对坐标系和符号 |
| 障碍消失后不恢复 | 点云/航点/正常命令是否都持续新鲜 | 恢复连续输入；不要增加第二个仲裁器 |

### 必做断链测试

执行机构断开时逐项停止点云、航点、正常命令，并测试错误 frame、重复时间戳、全 NaN 点云和完全封路。每种情况最终 `/cmd_vel` 都必须为零；障碍消失且三路输入恢复后才允许回到正常命令。

## 7. 推荐调参顺序

1. 实测并审核雷达外参、车体长宽和 `base_link` 位置。
2. 在已知位置摆放障碍物，用 PointCloud2 bag 校准高度带、ROI、自车裁剪、栅格尺寸和点数阈值。
3. 按安全余量设置 footprint 与 `inflation_m`，先宁可停车，不要漏碰撞。
4. 断开执行机构核对 `linear.x`、`angular.z` 符号，再加载审核后的首次联调速度和曲率限制。
5. 调 `horizon_m`、`curvature_samples`，确保计算稳定且左右均能找到合理轨迹。
6. 最后小幅调整目标/航向/曲率/间距评分权重。
7. 依据实测输入周期设置三个超时，并重复无障碍透传、遇障接管、障碍释放、完全封路和所有断链测试。
