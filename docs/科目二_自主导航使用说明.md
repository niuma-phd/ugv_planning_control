# 科目二顺序航点控制与现场调参说明

本文对应当前生产代码。RDK 断开期间只能完成代码与离线测试；实车运动、制动距离和参数效果仍由现场人员验证。

## 1. 当前控制链

```text
/livox_odometry_mapped  (LIO: world -> livox_frame)
  -> lio_odom_adapter   (六轴外参换算)
  -> /localization/odom (odom -> base_link)
  -> waypoint_controller_node
  -> /cmd_vel

map_odom_manager
  -> map -> odom（当前固定为配置中的初始变换，默认全 0）
```

生产 launch 不再启动 `odom_guard_node` 和 `recovery_coordinator_node`。控制器也不再订阅：

- `/localization/trusted_odom`
- `/localization/odom_valid`
- `/localization/navigation_enabled`

控制器每收到一帧 `/localization/odom` 就立即计算并发布一次命令，不检查 odom header 时间戳、不判断新鲜度、不比较时间先后，也不做跳变阈值锁存。仍保留以下最小输入检查：话题和 frame 必须匹配，位姿和控制计算必须是有限数，`map -> odom` TF 必须可用。

这意味着：LIO 的“漂没漂”不再由时间或单帧 guard 判断；后续若要加漂移判断，应根据位姿数值另行设计。若 LIO 停止发布，控制节点也停止产生新命令，因此底盘侧必须保留独立的 `/cmd_vel` 接收超时停车看门狗。

GPS 可独立启动和观察，但不参与逐帧航点控制。

## 2. 航点执行规则

CSV 在节点启动时一次性完整加载，运行中不热更新。控制器把每一行看成有顺序的队列：

1. 启动后只认第 1 个航点，不在整条路径中搜索“最近点”。
2. 第 1 个航点确认后，目标才切换到第 2 个；之后依次切换，不会主动跳到更后面的 CSV 行。
3. 首点和中间点使用 `waypoint_tolerance` 确认；车体越过当前线段终点且横向误差仍在该容差内，也算通过，避免轻微冲过后倒回。
4. 最终点只使用独立的 `goal_tolerance` 判断。只有前面各点已按序确认，最终点才可能触发停车。
5. 最终点到达后零速锁存；即使定位随后变化也不会重新起步。要重新跑一遍，安全停车后重启控制 launch。
6. 第 1 个航点尚未确认时直接追第 1 点；从第 2 点开始，当前位置只投影到当前未确认航段，随后沿该航段向前插值得到前视点。前视点最多到达当前必达航点，确认后的下一帧才进入下一段，因此回折、自交路径也不会打乱 CSV 顺序。
7. 航向误差达到 `turn_in_place_threshold_rad`，或者当前目标落到车体后方时，进入 `ALIGN`：线速度严格为 0。起转阶段角速度非零时至少为 `minimum_turning_yaw_rate`；LIO yaw 已变化 `turning_motion_threshold_rad` 后，确认克服静摩擦并降到运动角速度下限。只有误差降到更小的 `turn_in_place_exit_threshold_rad` 才恢复 `TRACK`，避免在边界反复切换。
8. `TRACK` 将当前位置投影到当前有序航段，再沿该段前进动态前视距离并插值得到追踪点；若剩余航段更短则钳到当前必达航点。随后使用标准 `kappa=2*y/L^2`、`omega=v*kappa`。非零线速度至少为 `minimum_linear_speed`；原始角速度越过进入阈值后，实际非零角速度至少为 `minimum_tracking_yaw_rate`。

CSV 的 `x_m/y_m` 用于当前二维控制；`z_m/yaw_rad` 会被格式校验，但目前不参与运动命令计算。

现场常用 `/home/sunrise/waypoints.csv` 共 5 点、总长约 101.495 m，相邻点距为 21.553--27.613 m，最大相邻航段转角约 6.472°。因此生产值在 `0.50 m/s` 巡航时使用 `2.00 m` 前视距离，并把中间点和终点容差设为 `0.50 m`；这些数值不是对所有路线通用。

## 3. 控制终端状态日志

启动后终端会显示航点总数和直接 odom 输入，例如：

```text
Loaded 24 ordered waypoints ... direct odom input is '/localization/odom'
[WAYPOINT] going to 1/24 (x=0.000, y=0.000)
[WAYPOINT] reached 1/24 (x=0.000, y=0.000)
[WAYPOINT] going to 2/24 (x=1.200, y=0.300)
```

运行状态约每秒打印一次，不会按 LIO 帧率刷屏：

```text
[WAYPOINT] tracking 2/24 | pose=(0.420, 0.070, yaw=0.120) | distance=0.816 | pursuit=(2.410, 0.000) seg=2 Ld=2.000 | path_yaw=0.000 ref_yaw=-0.035 yaw_error=-0.155 cross_track=0.070 | raw=(v=0.494, omega=-0.035) | cmd=(v=0.500, omega=0.000) floor=(v:yes, omega:no)
[WAYPOINT] aligning to 3/24 | pose=(1.190, 0.290, yaw=0.150) | distance=1.006 | path_yaw=-1.571 ref_yaw=-1.571 yaw_error=-1.721 cross_track=0.000 | raw=(v=0.000, omega=-1.721) | cmd=(v=0.000, omega=-1.500) floor=(v:no, omega:no)
```

含义：

- `tracking`：正在向当前航点前进。
- `aligning to`：当前只原地转向，`v=0`。
- `pursuit`：从当前航段投影点向当前必达点前进 `Ld` 后插值得到的标准 Pure Pursuit 目标；不会越过尚未确认的 CSV 行，`seg` 是当前航段终点序号。
- `path_yaw`：前视点所在航段方向；`ref_yaw`：车辆指向前视点的方向。
- `yaw_error`：`ref_yaw - 当前 yaw`，已归一化到 `[-pi, pi]`；正值左转，负值右转。
- `cross_track`：相对当前航段的横向误差；正值表示车辆在航段左侧，负值表示在右侧。
- `raw` 是死区和最低输出整形前的计算值；`cmd` 是实际发布值；`floor=yes` 表示该轴被抬到了底盘最低有效输出；`breakaway=yes` 表示原地转向仍处于 `1.50` 起转阶段。
- `reached`：当前点已进入容差；`passed`：未进容差圈，但已从允许的横向误差内越过该点。
- `final waypoint ... reached`：最终点已到达，零速已锁存。

同时可在另一个终端观察：

```bash
ros2 topic echo /subject2/target_point
ros2 topic echo /cmd_vel
```

## 4. 参数与运动效果

参数位于 `waypoint_controller_node.ros__parameters`。全部只在节点启动时读取；改 YAML 后必须停止并重启控制 launch，无需重启 LIO。

| 参数 | 当前仓库值 | 增大后的主要效果 | 减小后的主要效果 |
|---|---:|---|---|
| `enhanced_tracking_enabled` | `true` | 启用路径投影、折线插值标准 Pure Pursuit、滞回和最低输出；设为 `false` 可回到旧的直接追单个航点逻辑 | — |
| `nominal_speed` | `0.50 m/s` | 直线和缓弯巡航更快 | 整体更慢、更易观察和停车 |
| `max_speed` | `1.00 m/s` | 只放宽硬上限；若 `nominal_speed` 仍为 `0.50`，车不会因此自动跑到 `1.00` | 更早限制所有前进速度 |
| `minimum_linear_speed` | `0.50 m/s` | 非零前进命令更容易克服底盘死区，但终点冲过量可能增加 | 低速更柔和；低于底盘门槛时可能只有命令、车辆不动 |
| `minimum_tracking_yaw_rate` | `1.00 rad/s` | 行驶中的有效纠偏更强，同时弯曲半径更小、动作更猛 | 纠偏更柔和；低于底盘运动中门槛时可能不转 |
| `minimum_turning_yaw_rate` | `1.50 rad/s` | 原地起转能力更强、对准更快 | 低于底盘静止门槛时可能无法起转 |
| `max_yaw_rate` | `1.50 rad/s` | 放宽所有转向输出上限 | 限制转向；不得小于两个最低角速度，否则节点拒绝启动 |
| `max_curvature` | `1.00 1/m` | 允许更紧的前进弯；对应几何最小半径约变小 | 转弯更缓，可能更易切不过急弯 |
| `lookahead_min_m` | `1.50 m` | 低速/终点附近也看得更远，轨迹更平滑但可能切弯 | 贴线更积极，但过小容易蛇形 |
| `lookahead_max_m` | `3.00 m` | 允许高速时看得更远；必须不小于最小前视 | 限制前视距离，急弯响应更快 |
| `lookahead_speed_gain` | `1.00 s` | 前视距离随计划速度增长得更快 | 前视距离更接近固定的最小值；设为 `0` 即固定前视 |
| `turning_motion_threshold_rad` | `0.05`（约 2.9°） | 需要确认更明显的原地转动才从 `1.50` 降到运动下限，可抗 LIO yaw 噪声但起转冲量更久 | 更快降到运动下限；过小可能把静止 yaw 噪声误认成已经转动 |
| `turn_in_place_threshold_rad` | `0.70`（约 40°） | 允许更大的误差边走边转 | 更早进入原地对准 |
| `turn_in_place_exit_threshold_rad` | `0.20`（约 11.5°） | 更早退出原地对准，但恢复行走时剩余误差更大 | 对准得更正后才行走，但原地转向时间更长；必须小于进入阈值 |
| `tracking_omega_enter_threshold_rad_s` | `0.05 rad/s` | 需要更大的标准 PP 原始角速度才触发 `1.00` 纠偏，直线更安静 | 更早触发纠偏，可能更频繁 |
| `tracking_omega_exit_threshold_rad_s` | `0.02 rad/s` | 已启动纠偏后更早归零 | 纠偏持续更久；必须小于进入阈值 |
| `slowdown_distance` | `1.20 m` | 只降低日志中的原始线速度；启用 `0.50` 最低线速度后，实际非零命令仍不会低于 `0.50` | 更靠近终点才产生原始减速 |
| `waypoint_tolerance` | `0.50 m` | 首点/中间点更容易通过，但压点精度降低、转角可能更早切换 | 压中间点更准，但过小会因定位噪声或横向偏差卡在某一点 |
| `goal_tolerance` | `0.50 m` | 离最终点较远即可锁停 | 终点更精确，但过小可能在终点附近反复调整而不结束 |
| `transform_timeout_sec` | `0.05 s` | 单次等待 `map -> odom` TF 更久 | TF 尚未可用时更快输出零速；它不是 odom 新鲜度检测 |

最低输出的应用顺序是固定的：

1. 无效输入、TF 失败和最终点到达首先输出严格双零，最低输出绝不介入。
2. `ALIGN` 始终保持 `v=0`；起转时非零命令抬到 `minimum_turning_yaw_rate`，累计 yaw 变化达到 `turning_motion_threshold_rad` 后使用较低的 `minimum_tracking_yaw_rate`。
3. `TRACK` 先用进入/退出阈值决定是否真的需要转向；不需要时 `omega=0`，需要时才抬到 `minimum_tracking_yaw_rate`。
4. 角速度需要由正变负或由负变正时，中间强制至少出现一帧零角速度，避免 LIO 噪声导致 `+1/-1` 每帧翻转。
5. 启用 `minimum_linear_speed=0.50` 后，终点附近不能平滑输出小于 `0.50` 的速度，而是保持 `0.50` 到进入 `goal_tolerance` 后直接锁零。这是克服已确认底盘死区的取舍。

建议现场每次只改一类参数，并记录修改前后日志：

1. 先用低 `nominal_speed` 确认坐标轴、左右转符号、航点顺序和底盘急停。
2. 原地不转，先核对 `minimum_turning_yaw_rate`；行驶纠偏不生效，核对 `minimum_tracking_yaw_rate`。两者不得高于 `max_yaw_rate`。
3. 直线左右摆，优先增大 `tracking_omega_enter_threshold_rad_s` 或 `lookahead_min_m`，不要先继续增大最低角速度。
4. 横向偏差回线太慢，小步减小 `lookahead_min_m`；回线过猛或蛇形则增大它。
5. 转角处希望更早原地对准，减小 `turn_in_place_threshold_rad`；希望更多边走边转则小步增大，但必须保持在 `(0, 1.5708]`。
6. 原地对准在阈值附近反复切换，减小退出阈值或增大进入阈值，始终保证退出值小于进入值。
7. 中间点卡住只调 `waypoint_tolerance`；最终停车问题优先调 `goal_tolerance`。最低线速度启用时，增大 `slowdown_distance` 不会产生低于 `0.50` 的实际输出。

`waypoint_tolerance` 应明显小于 CSV 中最短的有效相邻点距。若它不小于最短点距，启动终端会给出警告；此时同一帧位姿可能按顺序确认多个相邻短航段。
8. 要测试 `1.00 m/s`，必须同时把 `nominal_speed` 调到目标值；`max_speed=1.00` 本身只是一道上限。

## 6. 从全部程序未启动到压航点

终端 A 启动用户已确认的雷达驱动和 LIO：

```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=0
/home/sunrise/ws_livox/rdk_lio_tmux.sh start
```

终端 B 启动控制。以下命令使用用户已确认的航点路径 `/home/sunrise/waypoints.csv` 和六轴全 0 外参；它不会另起一份雷达驱动或 LIO：

```bash
source /opt/ros/humble/setup.bash
source /home/sunrise/ugv_planning_control_ws_lio_guidance/install_subject2/setup.bash
export ROS_DOMAIN_ID=0

ros2 launch ugv_subject2_bringup subject2.launch.py \
  config_file:=/home/sunrise/subject2_field.yaml \
  waypoint_file:=/home/sunrise/waypoints.csv \
  lidar_extrinsics_valid:=true \
  publish_lidar_static_tf:=false \
  lidar_extrinsics_provenance:=user-confirmed-zero-extrinsics \
  base_to_lidar_x:=0.0 \
  base_to_lidar_y:=0.0 \
  base_to_lidar_z:=0.0 \
  base_to_lidar_roll:=0.0 \
  base_to_lidar_pitch:=0.0 \
  base_to_lidar_yaw:=0.0
```

停止顺序：先在终端 B 用 `Ctrl-C` 停控制并确认车辆停止，再执行：

```bash
/home/sunrise/ws_livox/rdk_lio_tmux.sh stop
```

本说明中的启动命令由现场用户执行；代码修改和离线验证不构成实车运动验收。
