# 科目二顺序航点控制与现场调参说明

本文对应 v1.1.0 生产代码。核心控制器已在当前 RDK S100 履带式差速车上完成多轮闭环调试，最终参数形态由现场操作人员确认基本可用。该结论只适用于当前车辆、场地、LIO、底盘、电池和航点组合。

## 1. 当前控制链

```text
/livox_odometry_mapped  (LIO: world -> livox_frame)
  -> lio_odom_adapter   (六轴外参换算)
  -> /localization/odom (odom -> base_link)
  -> waypoint_controller_node
  -> /cmd_vel

map_odom_manager
  -> map -> odom（当前固定为配置中的初始变换，默认全 0）
```

生产 launch 不再启动 `odom_guard_node` 和 `recovery_coordinator_node`。控制器也不再订阅：

- `/localization/trusted_odom`
- `/localization/odom_valid`
- `/localization/navigation_enabled`

控制器每收到一帧 `/localization/odom` 就计算并缓存一次命令；独立 wall timer 再按 `command_publish_rate_hz` 发布缓存值。它不检查 odom header 时间戳、不比较时间先后，也不做跳变阈值锁存。仍保留以下最小输入检查：话题和 frame 必须匹配，位姿和控制计算必须是有限数，`map -> odom` TF 必须可用。

这意味着：LIO 的“漂没漂”不再由时间或单帧 guard 判断；后续若要加漂移判断，应根据位姿数值另行设计。若长时间没有新的可用控制结果，命令租约过期后 timer 改发零速。当前 `0.5 Hz + 4.10 s` 配置的最坏响应可能接近 6 秒，因此底盘侧仍必须保留独立的 `/cmd_vel` 接收超时停车看门狗和现场急停。

GPS 可独立启动和观察，但不参与逐帧航点控制。

## 2. 航点执行规则

CSV 在节点启动时一次性完整加载，运行中不热更新。控制器把每一行看成有顺序的队列：

1. 启动后只认第 1 个航点，不在整条路径中搜索“最近点”。
2. 第 1 个航点确认后，目标才切换到第 2 个；之后依次切换，不会主动跳到更后面的 CSV 行。
3. 首点和中间点使用 `waypoint_tolerance` 确认；车体越过当前线段终点且横向误差仍在该容差内，也算通过，避免轻微冲过后倒回。
4. 最终点只使用独立的 `goal_tolerance` 判断。只有前面各点已按序确认，最终点才可能触发停车。
5. 最终点到达后零速锁存；即使定位随后变化也不会重新起步。要重新跑一遍，安全停车后重启控制 launch。
6. 第 1 个航点尚未确认时直接追第 1 点；从第 2 点开始，当前位置只投影到当前未确认航段，随后沿该航段向前插值得到前视点。前视点最多到达当前必达航点，确认后的下一帧才进入下一段，因此回折、自交路径也不会打乱 CSV 顺序。
7. 航向误差达到 `turn_in_place_threshold_rad`，或者当前目标落到车体后方时，进入 `ALIGN`：线速度严格为 0，整个 ALIGN 阶段的非零角速度都至少为 `minimum_turning_yaw_rate`。只有误差降到更小的 `turn_in_place_exit_threshold_rad` 才恢复 `TRACK`，避免在边界反复切换。
8. `TRACK` 将当前位置投影到当前有序航段，再沿该段前进动态前视距离并插值得到追踪点；若剩余航段更短则钳到当前必达航点。随后使用标准 `kappa=2*y/L^2`、`omega=v*kappa`。非零线速度至少为 `minimum_linear_speed`；原始角速度越过进入阈值后，实际非零角速度至少为 `minimum_tracking_yaw_rate`。

CSV 的 `x_m/y_m` 用于当前二维控制；`z_m/yaw_rad` 会被格式校验，但目前不参与运动命令计算。

当前实车 profile 使用 `1.5 m/s` 巡航、`8--12 m` 动态前视，并把中间点和终点容差设为 `2.0 m`，以减少稀疏航点路线上的频繁急转和蛇形。参数是否适合仍取决于相邻点距和弯角，不能直接套到其他路线。

## 3. 控制终端状态日志

启动后终端会显示航点总数和直接 odom 输入，例如：

```text
Loaded 24 ordered waypoints ... direct odom input is '/localization/odom'
[WAYPOINT] going to 1/24 (x=0.000, y=0.000)
[WAYPOINT] reached 1/24 (x=0.000, y=0.000)
[WAYPOINT] going to 2/24 (x=1.200, y=0.300)
```

运行状态约每秒打印一次，不会按 LIO 帧率刷屏：

```text
[WAYPOINT] tracking 2/24 | pose=(0.420, 0.070, yaw=0.120) | distance=20.816 | pursuit=(11.410, 0.000) seg=2 Ld=11.000 | path_yaw=0.000 ref_yaw=-0.005 yaw_error=-0.125 cross_track=0.070 | raw=(v=1.500, omega=-0.034) | controller=(v=1.500, omega=0.000) floor=(v:no, omega:no) breakaway=no
[ACTUATION] generation=315 pulse=no demand_omega=0.000 published=(v=1.500, omega=0.000)
```

含义：

- `tracking`：正在向当前航点前进。
- `aligning to`：当前只原地转向，`v=0`。
- `pursuit`：从当前航段投影点向当前必达点前进 `Ld` 后插值得到的标准 Pure Pursuit 目标；不会越过尚未确认的 CSV 行，`seg` 是当前航段终点序号。
- `path_yaw`：前视点所在航段方向；`ref_yaw`：车辆指向前视点的方向。
- `yaw_error`：`ref_yaw - 当前 yaw`，已归一化到 `[-pi, pi]`；正值左转，负值右转。
- `cross_track`：相对当前航段的横向误差；正值表示车辆在航段左侧，负值表示在右侧。
- `raw` 是死区和最低输出整形前的计算值；`controller` 是缓存前的控制器输出；`floor=yes` 表示该轴被抬到了底盘最低有效输出；`breakaway` 只记录原地 yaw 是否已经产生可观察变化。
- `[ACTUATION]` 才是固定频率 timer 实际发布到 `/cmd_vel` 的命令；`generation` 是缓存更新代数，`pulse` 表示是否使用行进角速度脉冲。
- `reached`：当前点已进入容差；`passed`：未进容差圈，但已从允许的横向误差内越过该点。
- `final waypoint ... reached`：最终点已到达，零速已锁存。

同时可在另一个终端观察：

```bash
ros2 topic echo /subject2/target_point
ros2 topic echo /cmd_vel
```

## 4. 参数与运动效果

参数位于 `waypoint_controller_node.ros__parameters`。全部只在节点启动时读取；改 YAML 后必须停止并重启控制 launch，无需重启 LIO。

| 参数 | 当前仓库值 | 增大后的主要效果 | 减小后的主要效果 |
|---|---:|---|---|
| `enhanced_tracking_enabled` | `true` | 启用路径投影、折线插值标准 Pure Pursuit、滞回和最低输出；设为 `false` 可回到旧的直接追单个航点逻辑 | — |
| `nominal_speed` | `1.5 m/s` | 直线和缓弯巡航更快 | 整体更慢；低于底盘有效门槛时可能走停 |
| `max_speed` | `1.5 m/s` | 只放宽硬上限，不会单独提高巡航 | 更早限制所有前进速度；不得小于最低线速度 |
| `minimum_linear_speed` | `1.0 m/s` | 非零前进命令更容易克服底盘死区，但终点冲过量可能增加 | 更柔和；低于底盘门槛时可能有命令但不动 |
| `minimum_tracking_yaw_rate` | `0.10 rad/s` | 行驶纠偏更容易产生动作，也更可能蛇形 | 纠偏更平滑；过低时底盘可能不响应 |
| `minimum_turning_yaw_rate` | `2.0 rad/s` | 原地起转更有力 | 过低时可能无法克服静摩擦 |
| `max_yaw_rate` | `2.0 rad/s` | 放宽所有转向输出上限 | 限制转向；不得小于两个最低角速度 |
| `max_curvature` | `0.10 1/m` | 允许更紧的行进弯 | 转向更缓、抑制蛇形，但急弯可能切不过去 |
| `lookahead_min_m` | `8.0 m` | 路径更平滑，过大时切弯 | 更贴线，过小容易蛇形 |
| `lookahead_max_m` | `12.0 m` | 允许高速时看得更远；必须不小于最小前视 | 急弯响应更快 |
| `lookahead_speed_gain` | `2.0 s` | 前视随计划速度增长更快 | 更接近固定最小前视；设 `0` 即固定前视 |
| `turning_motion_threshold_rad` | `0.05` | 只影响原地运动确认日志，不再降低 ALIGN 角速度下限 | 同左；过小会把 yaw 噪声当作已运动 |
| `turn_in_place_threshold_rad` | `1.50`（约 86°） | 允许更大的误差边走边转 | 更早停下原地对准 |
| `turn_in_place_exit_threshold_rad` | `0.70`（约 40°） | 更早恢复行走，剩余误差更大 | 对得更正后再走；必须小于进入阈值 |
| `tracking_omega_enter_threshold_rad_s` | `0.075 rad/s` | 更不容易启动行进纠偏，直线更安静 | 更早纠偏，可能更频繁 |
| `tracking_omega_exit_threshold_rad_s` | `0.040 rad/s` | 已启动纠偏后更早归零 | 纠偏持续更久；必须小于进入阈值 |
| `slowdown_distance` | `5.0 m` | 更早产生原始减速 | 更靠近终点才减速 |
| `waypoint_tolerance` | `2.0 m` | 中间点更容易通过，减少突然拐回压点 | 压点更准，但可能卡点或急转 |
| `goal_tolerance` | `2.0 m` | 离最终点较远即可锁停 | 终点更精确，过小可能反复调整 |
| `transform_timeout_sec` | `0.05 s` | 单次等待 `map -> odom` TF 更久 | TF 尚未可用时更快输出零速；它不是 odom 新鲜度检测 |
| `command_publish_rate_hz` | `0.5 Hz` | 更频繁刷新底盘命令、转向变化更细 | 命令保持更久、动作更粗；必须确认底盘兼容 |
| `command_hold_timeout_sec` | `4.10 s` | 容忍更长的控制结果间隔，但故障停车更慢 | 更快因租约过期置零；必须严格大于两个发布周期 |
| `tracking_yaw_pulse_enabled` | `false` | 设 `true` 后可把小角速度整形成脉冲；可能引入摆动 | `false` 直接发布控制器角速度 |
| `tracking_yaw_min_pulse_sec` | `2.00 s` | 启用脉冲时单次动作更长 | 单次动作更短，底盘可能来不及响应 |
| `tracking_yaw_demand_gain` | `1.0` | 启用脉冲时更快积累需求 | 脉冲更少 |
| `stall_boost_enabled` | `false` | 设 `true` 后检测到有命令但位姿不动时临时增大控制量 | `false` 完全旁路该机制；这是当前实车基线 |

最低输出的应用顺序是固定的：

1. 无效输入、TF 失败和最终点到达首先输出严格双零，最低输出绝不介入。
2. `ALIGN` 始终保持 `v=0`；整个阶段的非零角速度都抬到 `minimum_turning_yaw_rate`，直到退出 ALIGN。
3. `TRACK` 先用进入/退出阈值决定是否真的需要转向；不需要时 `omega=0`，需要时才抬到 `minimum_tracking_yaw_rate`。
4. 角速度需要由正变负或由负变正时，中间强制至少出现一帧零角速度，避免 LIO 噪声导致 `+1/-1` 每帧翻转。
5. 启用 `minimum_linear_speed=1.0` 后，终点附近不能平滑输出小于 `1.0` 的速度，而是保持最低速度到进入 `goal_tolerance` 后直接锁零。这是克服底盘死区的取舍。
6. 当前 profile 的 yaw pulse 和 stall boost 都关闭，不改变上述输出；只有显式启用后相应整形才介入。

建议现场每次只改一类参数，并记录修改前后日志：

1. 先用低 `nominal_speed` 确认坐标轴、左右转符号、航点顺序和底盘急停。
2. 原地不转，先核对 `minimum_turning_yaw_rate`；行驶纠偏不生效，核对 `minimum_tracking_yaw_rate`。两者不得高于 `max_yaw_rate`。
3. 直线左右摆，优先增大 `tracking_omega_enter_threshold_rad_s` 或 `lookahead_min_m`，不要先继续增大最低角速度。
4. 横向偏差回线太慢，小步减小 `lookahead_min_m`；回线过猛或蛇形则增大它。
5. 转角处希望更早原地对准，减小 `turn_in_place_threshold_rad`；希望更多边走边转则小步增大，但必须保持在 `(0, 1.5708]`。
6. 原地对准在阈值附近反复切换，减小退出阈值或增大进入阈值，始终保证退出值小于进入值。
7. 中间点卡住只调 `waypoint_tolerance`；最终停车问题优先调 `goal_tolerance`。最低线速度启用时，增大 `slowdown_distance` 不会产生低于 `minimum_linear_speed` 的实际输出。

`waypoint_tolerance` 应明显小于 CSV 中最短的有效相邻点距。若它不小于最短点距，启动终端会给出警告；此时同一帧位姿可能按顺序确认多个相邻短航段。
8. 要测试新的巡航速度，必须同时把 `nominal_speed` 调到目标值；`max_speed` 本身只是一道上限。

## 6. 从全部程序未启动到压航点

终端 A 启动用户已确认的雷达驱动和 LIO：

```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=0
/home/sunrise/ws_livox/rdk_lio_tmux.sh start
```

终端 B 启动控制。以下命令使用用户已确认的航点路径 `/home/sunrise/waypoints.csv` 和六轴全 0 外参；它不会另起一份雷达驱动或 LIO：

```bash
source /opt/ros/humble/setup.bash
source /home/sunrise/ugv_planning_control_ws_lio_guidance/install_subject2/setup.bash
export ROS_DOMAIN_ID=0

ros2 launch ugv_subject2_bringup subject2.launch.py \
  config_file:=/home/sunrise/subject2_field.yaml \
  waypoint_file:=/home/sunrise/waypoints.csv \
  lidar_extrinsics_valid:=true \
  publish_lidar_static_tf:=false \
  lidar_extrinsics_provenance:=user-confirmed-zero-extrinsics \
  base_to_lidar_x:=0.0 \
  base_to_lidar_y:=0.0 \
  base_to_lidar_z:=0.0 \
  base_to_lidar_roll:=0.0 \
  base_to_lidar_pitch:=0.0 \
  base_to_lidar_yaw:=0.0
```

停止顺序：先用现场急停或已验证的底盘机制确认车辆已经停止，再在终端 B 用 `Ctrl-C` 停控制。进程退出不保证额外发送最后一帧零速。确认车辆保持停止后再执行：

```bash
/home/sunrise/ws_livox/rdk_lio_tmux.sh stop
```

本说明中的启动命令由现场用户执行；代码修改和离线验证不构成实车运动验收。
