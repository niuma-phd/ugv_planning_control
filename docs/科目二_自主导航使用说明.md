# 科目二自主导航使用说明

本文只描述当前仓库已经实现的科目二闭环。当前方案面向两轮差速履带车：Horizon 雷达与现有 LIO 提供位姿，上游持续发布全局路径，本仓库输出标准 `/cmd_vel`。现阶段临时假定 `map` 与 `odom` 原点和轴向一致。

> **安全边界**：尚未完成雷达外参、车辆限速/制动、下游看门狗和实车故障测试前，不得把非零 `/cmd_vel` 接到执行机构。

## 1. 代码位置与数据流

| 模块 | 代码 | 作用 |
|---|---|---|
| LIO 里程计适配 | `src/ugv_localization_mvp/src/lio_odom_adapter_node.cpp` | 将 LIO 的 `world→livox_frame` 位姿换算为规范的 `odom→base_link` |
| 里程计保护 | `src/ugv_localization_mvp/src/odom_guard_node.cpp`、`odom_guard_core.cpp` | 检查时间戳、坐标系、数值、四元数和位姿跳变；故障锁存并保存最后可信值 |
| `map→odom` 管理 | `src/ugv_localization_mvp/src/map_odom_manager_node.cpp` | 当前按科目二配置发布恒等变换 |
| 路径控制节点 | `src/ugv_subject2_mvp/src/waypoint_controller_node.cpp` | 检查输入时效、做 TF 转换、周期性发布控制指令 |
| Pure Pursuit 核心 | `src/ugv_subject2_mvp/src/pure_pursuit_controller.cpp` | 搜索路径进度、选前视点、计算曲率、末端减速 |
| 启动与参数 | `src/ugv_subject2_bringup/launch/subject2*.launch.py`、`config/subject2.yaml` | 连接 Horizon、LIO、定位和控制节点 |

完整链路：

```text
Horizon PointCloud2 /livox/lidar + /livox/imu
  → 现有 LIO（强制 msg_type=1）
  → /livox_odometry_mapped（world→livox_frame）
  → lio_odom_adapter
  → /localization/odom + TF odom→base_link
  → odom_guard
  → /localization/trusted_odom + /localization/odom_valid

上游 /subject2/path ─┐
可信里程计与 map→odom ├→ waypoint_controller_node → /cmd_vel
                     └→ /subject2/target_point（调试）
```

`subject2_horizon.launch.py` 还会把 LIO 原始 `/tf`、`/tf_static` 重映射到 `/lio_raw/tf`、`/lio_raw/tf_static`，避免原始 `world→livox_frame` 污染规范 TF 树。

## 2. 控制逻辑

每个控制周期按以下顺序执行：

1. 同时要求 `/localization/trusted_odom`、`/localization/odom_valid=true` 和非空 `/subject2/path`。
2. 用本机单调时钟检查接收时效：里程计不超过 `0.30 s`，有效标志不超过 `0.50 s`，路径不超过 `5.0 s`。
3. 要求里程计为 `header.frame_id=odom`、`child_frame_id=base_link`；利用最新 `map→odom` 把车体位姿变换到路径坐标系。
4. 路径内容变化时清零历史进度；正常运行时最近点索引只向前推进，最多回看 3 点、向前搜索 200 点，避免在交叉/回环路径上大幅倒退。
5. 从最近点沿路径累计前视距离，得到目标点。当前使用固定 `0.80 m` 前视距离。
6. 把目标点转到车体坐标系，按 `曲率 = 2 × y / (x² + y²)` 计算曲率，并限制曲率、线速度和角速度。
7. 距离终点不足 `1.20 m` 时线性减速；距终点不超过 `0.30 m` 时发布零速。
8. 任一输入缺失、过期、坐标系错误、TF 不可用、数值非法，或目标点落在车后方时，发布零速。

最终命令为 `geometry_msgs/msg/Twist`：

```text
linear.x  [m/s]    正值前进
angular.z [rad/s]  正值左转
其余分量           始终为 0
```

本仓库不输出履带转速、PWM 或 CAN 指令；底盘团队负责把车体线速度/角速度换算为左右履带命令，并实现独立硬件看门狗。

### 里程计保护的故障行为

`odom_guard` 会锁存以下故障：非有限数、四元数非法、数据过旧/来自未来、时间戳重复/倒退、坐标系不匹配、单帧平移或偏航跳变。锁存后：

- `/localization/odom_valid` 变为 `false`；
- 停止发布新的 `/localization/trusted_odom`；
- 控制器在下一控制周期输出零速；
- 如果故障前已经产生过可信样本，则将最后可信样本写入：
  - `/home/sunrise/.ros/ugv_mvp/last_good_subject2_odom.json`
  - `/home/sunrise/.ros/ugv_mvp/last_good_subject2_odom.csv`

排除根因后，人工复位：

```bash
ros2 service call /localization/reset_odom_fault std_srvs/srv/Trigger '{}'
```

复位会清空旧可信样本并保持 `odom_valid=false`，直到收到新的合格里程计。当前代码**不会**自动重启 LIO，也不会自动使用 GPS 续接。

## 3. 主要话题和节点

| 名称 | 类型 | 方向/用途 |
|---|---|---|
| `/livox/lidar` | `sensor_msgs/msg/PointCloud2` | Horizon → LIO |
| `/livox/imu` | `sensor_msgs/msg/Imu` | Horizon → LIO |
| `/livox_odometry_mapped` | `nav_msgs/msg/Odometry` | LIO → 适配器；必须是 `world→livox_frame` |
| `/localization/odom` | `nav_msgs/msg/Odometry` | 适配器输出，`odom→base_link` |
| `/localization/trusted_odom` | `nav_msgs/msg/Odometry` | 保护器输出 → 控制器 |
| `/localization/odom_valid` | `std_msgs/msg/Bool` | 保护器有效标志 → 控制器 |
| `/localization/last_trusted_odom` | `nav_msgs/msg/Odometry` | transient-local 调试/恢复依据 |
| `/subject2/path` | `nav_msgs/msg/Path` | 上游 → 控制器；有序路径点序列 |
| `/subject2/target_point` | `geometry_msgs/msg/PointStamped` | 当前前视点，仅用于诊断 |
| `/cmd_vel` | `geometry_msgs/msg/Twist` | 本仓库 → 底盘 |

启动后应看到：

```text
/lio_odom_adapter
/map_odom_manager
/odom_guard
/waypoint_controller_node
/scan_registration（外部 LIO，实际名称以部署为准）
```

## 4. 当前参数与调参含义

参数文件：`src/ugv_subject2_bringup/config/subject2.yaml`。

### 控制器

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `control_rate_hz` | 20.0 | 控制发布频率 |
| `nominal_speed` | 0.10 m/s | 正常目标速度 |
| `max_speed` | 0.20 m/s | 软件线速度上限 |
| `max_yaw_rate` | 0.40 rad/s | 软件偏航角速度上限 |
| `max_curvature` | 1.00 1/m | 曲率上限 |
| `lookahead_distance` | 0.80 m | 固定前视距离 |
| `use_speed_scaled_lookahead` | false | 当前禁用随速度变化的前视距离 |
| `min_lookahead` / `max_lookahead` | 0.50 / 1.50 m | 前视距离钳位范围 |
| `slowdown_distance` | 1.20 m | 进入终点减速的剩余路程 |
| `goal_tolerance` | 0.30 m | 到达终点判定半径 |
| `odom_timeout_sec` | 0.30 s | 控制器里程计接收超时 |
| `path_timeout_sec` | 5.0 s | 路径接收超时；上游须周期刷新 |
| `valid_timeout_sec` | 0.50 s | 有效标志接收超时 |
| `transform_timeout_sec` | 0.05 s | 单次 TF 查询等待上限 |

### 里程计保护

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `max_age_s` | 0.50 s | 数据时间戳最大年龄 |
| `future_tolerance_s` | 0.05 s | 允许的未来时间戳偏差 |
| `quaternion_norm_tolerance` | 0.05 | 四元数模长误差上限 |
| `max_translation_jump_m` | 1.50 m/帧 | 单帧平移跳变阈值 |
| `max_yaw_jump_rad` | 0.80 rad/帧 | 单帧偏航跳变阈值 |

这些值是保守候选值，不是实车认证值。调参顺序见第 8 节。

## 6. 启动命令

### 6.1 一条命令启动 Horizon、LIO 和科目二

先准备经过确认的 Horizon 白名单 JSON，以及测量审核过的 `base_link→livox_frame` 六自由度外参。`x/y/z` 单位为米，`roll/pitch/yaw` 单位为弧度。

```bash
source /opt/ros/humble/setup.bash
source /home/sunrise/livox_driver/install/setup.bash
source /home/sunrise/ws_livox/tunable-final/install/setup.bash
source /home/sunrise/ugv_planning_control_ws/install_subject2/setup.bash

ros2 launch ugv_subject2_bringup subject2_horizon.launch.py \
  start_driver:=true \
  start_lio:=true \
  driver_config:=/绝对路径/已确认的horizon白名单.json \
  driver_allow_auto_discovery:=false \
  publish_lidar_static_tf:=true \
  lidar_extrinsics_provenance:=外参测量记录编号 \
  base_to_lidar_x:=实测值 \
  base_to_lidar_y:=实测值 \
  base_to_lidar_z:=实测值 \
  base_to_lidar_roll:=实测值 \
  base_to_lidar_pitch:=实测值 \
  base_to_lidar_yaw:=实测值
```

必须替换所有中文占位符。只把 `publish_lidar_static_tf` 设为 `true`，但漏填来源或任一外参，launch 会直接报错退出。保持默认 `false` 时，适配器故意不发布规范里程计和 TF，车辆不会形成非零闭环。

### 6.2 外部已经启动驱动和 LIO

外部 LIO 必须等价地使用 PointCloud2 `msg_type=1`，并隔离原始 TF。然后只启动本仓库节点：

```bash
ros2 launch ugv_subject2_bringup subject2_horizon.launch.py \
  start_driver:=false \
  start_lio:=false \
  publish_lidar_static_tf:=true \
  lidar_extrinsics_provenance:=外参测量记录编号 \
  base_to_lidar_x:=实测值 base_to_lidar_y:=实测值 base_to_lidar_z:=实测值 \
  base_to_lidar_roll:=实测值 base_to_lidar_pitch:=实测值 base_to_lidar_yaw:=实测值
```

`subject2.launch.py` 也可只启动本地节点，外参参数相同。

## 7. 启动后调试与故障定位

先断开执行机构，再依次检查。

### 7.1 节点、类型和唯一发布者

```bash
ros2 node list
ros2 topic type /livox/lidar
ros2 topic type /livox_odometry_mapped
ros2 topic type /subject2/path
ros2 topic type /cmd_vel
ros2 topic info -v /cmd_vel
```

预期：`/livox/lidar` 为 `sensor_msgs/msg/PointCloud2`；`/cmd_vel` 为 `geometry_msgs/msg/Twist`，且科目二运行图中只有一个发布者。

### 7.2 频率、参数和 TF

```bash
ros2 topic hz /livox/lidar
ros2 topic hz /livox/imu
ros2 topic hz /livox_odometry_mapped
ros2 topic hz /localization/trusted_odom
ros2 topic hz /subject2/path
ros2 param get /scan_registration msg_type
ros2 run tf2_ros tf2_echo base_link livox_frame
ros2 run tf2_ros tf2_echo map odom
ros2 run tf2_ros tf2_echo odom base_link
```

预期：

- `msg_type` 为 `1`；
- `base_link→livox_frame` 与审核记录一致；
- 科目二的 `map→odom` 为恒等变换；
- `odom→base_link` 连续更新；
- `/subject2/path` 至少每 5 秒刷新一次，建议 1 Hz 或更高。

### 7.3 定位与命令

```bash
ros2 topic echo /localization/odom --once
ros2 topic echo /localization/trusted_odom --once
ros2 topic echo /localization/odom_valid
ros2 topic echo /subject2/target_point
ros2 topic echo /cmd_vel

```

### 7.4 常见现象

| 现象 | 优先检查 | 正确处理 |
|---|---|---|
| 没有 `/livox/lidar` | 雷达连接、白名单 JSON、驱动日志 | 先恢复 PointCloud2，不要绕过感知输入 |
| 有点云但无 `/livox_odometry_mapped` | LIO 是否启动、`msg_type=1`、IMU、LIO 配置 | 修复 LIO；不要改控制器掩盖定位故障 |
| 有原始里程计但无 `/localization/odom` | 原始 frame 是否为 `world/livox_frame`、外参是否启用 | 修正 frame 或加载审核外参 |
| `odom_valid=false` 持续不恢复 | 节点日志、最后可信快照、时间戳/跳变阈值 | 排除根因后调用复位服务 |
| 有可信里程计但 `/cmd_vel=0` | 路径是否为空/过期、TF、终点距离、目标点是否在车后 | 恢复新鲜合法路径和 TF |
| 左右转方向相反 | `angular.z` 正方向、车体系、底盘适配 | 断开执行机构核对符号；不要用路径参数补偿符号错误 |
| 路径交叉处跳点 | 点序、密度、`progress_search_ahead/backtrack` | 先修正有序路径，再小幅调搜索窗口 |
| 终点振荡或冲过终点 | `slowdown_distance`、`goal_tolerance`、定位噪声 | 先降低速度，再增大减速距离/容差 |

### 7.5 必做断链测试

在执行机构断开时，分别停止路径、LIO、雷达，或制造里程计超时，确认 `/cmd_vel` 变为全零。控制器在 `0.30 s` 接收超时后的下一次 20 Hz 控制周期停车；下游还必须有独立超时停车机制。

## 8. 推荐调参顺序

1. **先固定坐标系**：确认 Horizon/LIO 单位、轴向、外参和科目二恒等 `map→odom` 假设，不要围绕错误 TF 调控制器。
2. **核对底盘符号**：断开执行机构验证 `linear.x>0` 前进、`angular.z>0` 左转。
3. **直线低速**：先用审核后的首次联调速度设置 `nominal_speed` 和 `max_speed`。
4. **前视距离**：直线稳定后再跑左右弯；抖动时适当增大，切弯迟钝时适当减小。
5. **曲率/角速度**：依据履带车实测稳定能力设置 `max_curvature`、`max_yaw_rate`。
6. **终点行为**：调整 `slowdown_distance` 和 `goal_tolerance`。
7. **保护阈值**：从健康实车 bag 的周期、跳变 p99 数据设置超时和平移/偏航跳变阈值，不能直接把当前候选值当结论。
8. **最后做故障注入**：逐一验证路径、TF、LIO、雷达、时间戳和下游通信故障都能停车。
