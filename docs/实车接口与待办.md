## 1. 系统边界

当前车辆为两轮差速履带车，最终接口固定为：

```text
topic: /cmd_vel
type:  geometry_msgs/msg/Twist

linear.x   前进速度，m/s，正值向前
angular.z  偏航角速度，rad/s，正值左转
其他分量   必须为 0
```

本仓库不输出履带转速、PWM、油门、转角或 CAN 帧。左右履带换算、符号适配、硬件急停和独立命令超时看门狗由底盘团队负责。`Twist` 本身没有时间戳，因此底盘不能把“ROS 发布节点还活着”当作唯一安全条件。

主要接口：

| 方向 | 话题 | 类型 | 责任 |
|---|---|---|---|
| 输入 | `/livox/lidar` | `livox_interfaces/msg/CustomMsg` | 明日外部 tmux launcher 启动的 Horizon 驱动；LIO 使用 `msg_type=0` |
| 输入 | `/livox/imu` | `sensor_msgs/msg/Imu` | Horizon 驱动发布；量纲和重力缩放必须实测 |
| 输入 | `/livox_odometry_mapped` | `nav_msgs/msg/Odometry` | 外部 LIO 的 `world→livox_frame` 位姿 |
| 启动输入 | `waypoint_file` | 绝对 CSV 文件路径 | 用户指定；控制节点启动时完整加载一次 |
| 内部 | `/localization/odom` | `nav_msgs/msg/Odometry` | 规范 `odom→base_link` |
| 输出 | `/cmd_vel` | `geometry_msgs/msg/Twist` | 唯一最终车体速度命令 |

运行图中 `/cmd_vel` 必须恰好只有一个发布者。

## 2. TF 与外参责任

本仓库受管 LIO 模式的目标 TF 链：

```text
map → odom → base_link → livox_frame
```

- `base_link→livox_frame`：由本团队测量。只有受管 LIO 已隔离原始 TF 时才发布这条静态 TF。
- `odom→base_link`：本仓库根据 LIO 雷达位姿和已审核雷达外参计算。
- `map→odom`：当前发布配置中的固定初始变换，默认恒等；只适用于物理起点、航点原点和轴向已人工对齐的封闭场地。生产必须保持 `auto_align_from_path=false`，航点文件不得隐式改变该变换。
- 受管 LIO 模式会把原始 TF 隔离到 `/lio_raw/tf`、`/lio_raw/tf_static`。明日的外部 tmux LIO 不做该重映射，因此保留两个独立子树：`map→odom→base_link` 与 `world→livox_frame`，禁止再发 `base_link→livox_frame`。
- 其他传感器静态 TF 由对应团队测量；本团队提供坐标、精度和记录要求。

### 雷达静态外参测量记录

每次测量必须形成可追溯记录：

1. 明确 `base_link` 和 `livox_frame` 的物理原点与轴向。
2. 测量平移 `x/y/z`，单位 m；测量固定轴姿态 `roll/pitch/yaw`，单位 rad。
3. 记录工具、方法、日期、车辆载荷、安装状态和各轴不确定度。
4. 生成非空记录编号 `lidar_extrinsics_provenance`，由另一人复核。
5. 静止采集点云，验证地面高度、车头方向和已知目标物位置。
6. Horizon 与 Avia 若安装在同一机械位置，仍需分别记录传感器型号和实际安装复核结果，不能只复制数字。

只有同时提供六个有限数值、非空记录编号并设置 `lidar_extrinsics_valid:=true`，才会启用规范里程计数值换算。`publish_lidar_static_tf` 只决定是否额外发布 `base_link→livox_frame` 静态 TF；使用已发布 `world→livox_frame` TF 的外部 tmux LIO 时应设为 `lidar_extrinsics_valid:=true publish_lidar_static_tf:=false`，避免 `livox_frame` 出现双父节点。默认零值不是有效外参。

### GPS 恢复输入测量与回填

真实 GPS 方不必编写 ROS 2 程序，但必须提供可适配为 `map` 下 x/y/z/yaw、时间戳、有效状态和协方差的原始信息。本团队适配后必须保证 36 个协方差元素均为有限数，x/y/z/yaw 对应索引 `[0,7,14,35]` 严格大于 0；当前候选上限为位置 `4.0 m²`、yaw `0.25 rad²`。需回填：

```text
GPS/RTK 设备、解算程序及版本：________________
datum/投影/场地原点：____________________________
map X/Y/Z 轴向与单位：____________________________
时间源、同步方法和最大偏差：______________________
yaw 来源、正方向、可信速度/状态：________________
x/y/z/yaw 协方差或质量指标定义：________________
无效/降级/断流的原始状态表达：____________________
GPS 天线相对 base_link 的 x/y/z：____________________ m
天线外参测量方法、日期、不确定度、记录编号：________
```

GPGGA position-only 串口适配器已实现，设备路径为空时不启动；它只发布 `/gps/fix`、校验后
的原始语句和位置质量诊断。具体串口、波特率/帧格式、质量 profile 和真实接收机仍需现场验收。
GGA 不带 yaw，因此只作 position-only 采集和质量观察，不参与当前控制。
串口取证见[GPGGA 串口接入说明](GGA串口接入说明.md)。LIO 发布的 `/lidar`
(`sensor_msgs/msg/NavSatFix`) 只是 LIO 伪坐标容器，与雷达点云、LIO odom 一样禁止伪充真实
GPS 恢复输入。

## 3. 车辆参数回填

下列值必须来自实测或底盘团队批准值：

```text
车辆最大长度（含固定突出物）：______ m
车辆最大宽度（含履带）：______ m
车辆最大高度：______ m
最低离地间隙：______ m
是否可采用矩形 footprint：______
如否，base_link 下逆时针顶点：________________

base_link 物理位置：________________________________
base_link 相对车头、左缘、地面的尺寸：______________
规划/控制参考点相对 base_link 的 x/y/z：____________

最大允许前进速度：______ m/s
首次联调安全速度：______ m/s
最大稳定偏航角速度：______ rad/s
最大曲率：______ 1/m
最小转弯半径：______ m
最大线加速度：______ m/s²
最大减速度：______ m/s²
最大偏航角加速度：______ rad/s²
命令归零至开始减速的 95/99 分位延迟：______ / ______ s
指定低速停车距离：速度______ m/s，距离______ m
允许倒车：是 / 否
允许原地转向：是 / 否
```

建议测量方法：

- 速度/角速度：在低附着和高附着地面分别重复直线、定半径转弯，记录稳定段 p95。
- 加减速度：使用独立时间基准记录 `/cmd_vel`、底盘反馈和外部位置，计算斜率。
- 命令延迟：反复从稳定非零命令切换到零，统计底盘开始减速的 p95/p99。
- 停车距离：从首次联调速度开始，至少重复 10 次急停和正常归零，使用最差值而非均值。
- 履带符号：车辆可靠架起且履带离地后，由用户现场授权并操作小正值 `linear.x`、`angular.z` 测试，确认前进和左转方向；AI 只辅助观察和记录。
- 定位保护阈值：从健康 Horizon/LIO bag 统计周期、延迟、单帧平移和偏航增量，再设置超时与跳变阈值。

当前生产 YAML 中 `nominal_speed=0.5 m/s`、`max_speed=1.0 m/s`。后者只放宽硬上限，不会在前者不变时自动把巡航速度提升到 1.0 m/s；两者都不是实车安全认证结果。

## 4. 上车前门禁

### 4.1 雷达、LIO 与 TF

- 驱动、LIO 和本仓库固定到已审核提交。
- 明日的固定 tmux launcher 要求 `site_config/horizon.json` 中 `lidar_config` 为空并显式开启 Horizon 自动发现；必须以 launcher 自检通过为准，不与旧的白名单流程混用。
- 明日外部 tmux 模式确认 `/livox/lidar` 为 CustomMsg、LIO `msg_type=0`；不得同时启动仓库的 PointCloud2 受管 LIO 模式。
- 数值换算使用的 `base_link→livox_frame` 六轴外参与测量记录完全一致。
- 明日外部 tmux 模式下，`livox_frame` 在标准 `/tf` 中的唯一父节点为 `world`，本仓库只发布 `map→odom→base_link`。
- IMU 单位、重力缩放和时间同步已经用静止与运动数据确认。
- `start_lio=true` 的受管模式才有 supervisor 重启契约。明日外部 tmux launcher 没有 `/localization/restart_lio`、`/localization/lio_generation` 和 `/localization/lio_process_alive`，自动恢复为 NO-GO；故障后必须保持零速并人工重启完整栈。
- 必须验证“重启 service success”只代表新进程已启动；新 GPS、新 odom、`map→odom` 回显、guard 复位和最终一致性未全部通过前必须持续零速。

### 4.2 GPS 恢复

- 真实 GPS 适配器已用审核的 datum、轴向、时间和天线外参，发布 `map` 下含可信 yaw/协方差的 `/localization/gps_pose`。
- `/localization/gps_valid` 在 fix 降级、yaw 不可信、时间过期或断流时能及时置 false/停止刷新。
- GPS 协方差 36 项均有限，`[0,7,14,35]` 均严格大于 0；候选协方差上限、稳定窗口、最大锚点修正和最终一致性阈值均由真实数据标定。
- 无 GPS、重启失败、重启后 GPS/odom 不稳定、TF 回显或最终一致性失败都进入 `ABORTED`，且确认 `/cmd_vel` 始终全零。

### 4.3 全局航点文件

- 航点坐标、点序、现场一致性、文件版本和最终路径由用户负责。
- 启动人已通过 `waypoint_file` 提供审核后的绝对 CSV 路径。
- CSV 包含 `x_m,y_m` 必填列；`z_m,yaw_rad` 可选；点序、单位、非重合航段和全部有限数值已复核。
- CSV 不超过 `2 MiB`，单行不超过 `4096` 字节，航点不超过 `10000` 个。
- 航点固定为 `map` 坐标；其原点和方向满足当前 `map→odom` 假设，且 `auto_align_from_path=false`。
- 使用替代 `config_file` 时仍保持航点 frame 为 `map`，不得改成其他 frame。
- 路线在控制节点启动时一次性加载；改线前已安全停车，改线后重启控制 launch。
- 生产图不运行航点发布器，不依赖路径话题。

### 4.4 底盘与安全

- 真实上车的直线、转弯、制动和航点跟踪测试由用户本人操作。
- AI 只能在执行机构物理断开，或车辆可靠架起且车轮/履带离地时辅助静态验证、分析日志和调整配置；不得自行发布非零运动命令。
- 下游已确认 `linear.x>0` 前进、`angular.z>0` 左转。
- 下游独立看门狗、现场急停和遥控停车均有效。
- 车辆速度、角速度、曲率和停车距离已经回填并批准。
- 执行器断开测试全部通过后，才允许架空履带；架空测试通过后，才允许封闭场地低速测试。
